## 1. ระบบความปลอดภัยและการยืนยันตัวตน (`lib/auth.ts`)

ไฟล์นี้เป็นหัวใจหลักด้านความปลอดภัย ทำหน้าที่เข้ารหัส จัดการเซสชันคุกกี้ และตรวจสอบสิทธิ์ผู้ใช้

### 1.1 `authSecret()`
* **หน้าที่:** ดึงค่ารหัสลับของระบบ (Secret Key) จาก Environment Variable (`process.env.AUTH_SECRET`)
* **การทำงาน:** หากเซิร์ฟเวอร์ไม่ได้ตั้งค่าไว้ จะใช้ค่าสำรอง แต่ในระบบจริงจะใช้ค่าลับที่ปลอดภัยเพื่อใช้ในการเข้ารหัสลายเซ็นดิจิทัล
* **ผลลัพธ์ที่คืนค่า:** ข้อความ String รหัสลับ

### 1.2 `base64url(input)`
* **หน้าที่:** แปลงข้อมูลตัวอักษรหรือไบนารีให้อยู่ในรูปแบบ URL-Safe Base64
* **การทำงาน:** นำข้อมูลมา Encode โดยแทนที่เครื่องหมาย `+`, `/` และ `=` ด้วยอักขระที่สามารถส่งผ่าน URL และ Cookie ได้อย่างปลอดภัยโดยไม่พัง
* **ผลลัพธ์ที่คืนค่า:** ข้อความ String Base64URL

### 1.3 `sign(value)`
* **หน้าที่:** สร้างลายเซ็นดิจิทัล (Digital Signature) ด้วยวิธี HMAC-SHA256
* **การทำงาน:** นำข้อความที่ต้องการเซ็น มาผสมกับรหัสลับของระบบ (`authSecret`) แล้วแปลงผลลัพธ์เป็น Hash ทำให้มั่นใจได้ว่าข้อมูลจะไม่ถูกปลอมแปลง
* **ผลลัพธ์ที่คืนค่า:** ข้อความ String ลายเซ็นดิจิทัล

### 1.4 `safeCompare(a, b)`
* **หน้าที่:** เปรียบเทียบข้อความ 2 ข้อความโดยป้องกันการโจมตีแบบ Timing Attack
* **การทำงาน:** ใช้ฟังก์ชัน `timingSafeEqual` ของ Node.js ซึ่งจะใช้เวลาในการเปรียบเทียบเท่ากันเสมอ ไม่ว่าข้อความจะตรงกันตั้งแต่ตัวอักษรแรกหรือไม่ ป้องกันแฮกเกอร์จับเวลาในการเดารหัสผ่าน
* **ผลลัพธ์ที่คืนค่า:** `true` หากตรงกัน, `false` หากไม่ตรงกัน

### 1.5 `shouldUseSecureCookie()`
* **หน้าที่:** ตรวจสอบว่าควรส่ง Cookie ผ่านช่องทางที่ปลอดภัย (HTTPS Only) หรือไม่
* **การทำงาน:** ตรวจดูว่าระบบกำลังรันอยู่บน Production หรือ Vercel หรือไม่ หากใช่จะบังคับเปิดแฟล็ก `Secure`
* **ผลลัพธ์ที่คืนค่า:** `true` หรือ `false`

### 1.6 `hashPassword(password)`
* **หน้าที่:** เข้ารหัสผ่านของผู้ใช้ก่อนบันทึกลงฐานข้อมูล
* **การทำงาน:** สุ่มสร้าง Salt ขนาด 16 ไบต์ขึ้นมา แล้วนำไปผ่านอัลกอริทึม Scrypt (ซึ่งปลอดภัยและถอดรหัสยากกว่า MD5/SHA256 ทั่วไปมาก)
* **ผลลัพธ์ที่คืนค่า:** ข้อความในรูปแบบ `scrypt:[salt]:[hash]`

### 1.7 `verifyPassword(password, stored)`
* **หน้าที่:** ตรวจสอบว่ารหัสผ่านที่ผู้ใช้พิมพ์เข้ามา ตรงกับรหัสผ่านที่ถูกแฮชไว้ในฐานข้อมูลหรือไม่
* **การทำงาน:** แยกเอา Salt จากรหัสผ่านเดิม แล้วนำรหัสผ่านที่ผู้ใช้เพิ่งพิมพ์มาคำนวณ Scrypt ซ้ำอีกครั้ง จากนั้นใช้ `safeCompare` เปรียบเทียบผลลัพธ์
* **ผลลัพธ์ที่คืนค่า:** `true` หากรหัสผ่านถูกต้อง, `false` หากไม่ถูกต้อง

### 1.8 `createSessionToken(payload)`
* **หน้าที่:** สร้าง Token สำหรับการล็อกอินของผู้ใช้ (คล้าย JWT แต่มีน้ำหนักเบาและรวดเร็ว)
* **การทำงาน:** กำหนดวันหมดอายุ (7 วันนับจากปัจจุบัน) นำข้อมูลผู้ใช้ (userId, role) แปลงเป็น Base64 แล้วประทับลายเซ็นดิจิทัลต่อท้ายด้วยจุด `.` เช่น `[payload].[signature]`
* **ผลลัพธ์ที่คืนค่า:** ข้อความ String เซสชันโทเคน

### 1.9 `verifySessionToken(token)`
* **หน้าที่:** ตรวจสอบความถูกต้องของ Token ว่าเป็นของจริงและยังไม่หมดอายุหรือไม่
* **การทำงาน:** แยก Payload และ Signature ออกจากกัน ตรวจสอบว่าลายเซ็นตรงกับรหัสลับหรือไม่ และตรวจสอบว่าเวลาหมดอายุ (`exp`) ยังไม่ล่วงเลยเวลาปัจจุบัน
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์ข้อมูลผู้ใช้ (`SessionPayload`) หากถูกต้อง หรือ `null` หากไม่ผ่าน

### 1.10 `setSessionCookie(response, token)`
* **หน้าที่:** บันทึก Token ลงในคุกกี้ของเบราว์เซอร์ผู้ใช้
* **การทำงาน:** ตั้งชื่อคุกกี้ `portfolio_session` กำหนดให้เป็น `httpOnly: true` (ป้องกันไม่ให้ JavaScript ขโมยคุกกี้ได้) และ `sameSite: lax`
* **ผลลัพธ์ที่คืนค่า:** ไม่มี (แนบคุกกี้ไปกับ Response Header)

### 1.11 `clearSessionCookie(response)`
* **หน้าที่:** ลบคุกกี้เซสชันออกจากเบราว์เซอร์ (ใช้ตอน Logout)
* **การทำงาน:** ตั้งค่าคุกกี้ให้ว่างเปล่าและกำหนด `maxAge: 0` เพื่อให้เบราว์เซอร์ทำลายคุกกี้ทิ้งทันที
* **ผลลัพธ์ที่คืนค่า:** ไม่มี

### 1.12 `toSafeUser(user)`
* **หน้าที่:** กรองข้อมูลผู้ใช้ออกเฉพาะฟิลด์ที่ปลอดภัย ก่อนส่งให้หน้าบ้าน
* **การทำงาน:** ตัดฟิลด์ที่เป็นความลับออก (เช่น `passwordHash`) เหลือเฉพาะ ชื่อ, รหัสนักศึกษา, อีเมล, สิทธิ์ (role), สาขา, และชั้นปี
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์ `SafeUser`

### 1.13 `getCurrentUser()`
* **หน้าที่:** ค้นหาและดึงข้อมูลผู้ใช้ปัจจุบันที่กำลังล็อกอินอยู่
* **การทำงาน:** อ่านคุกกี้ `portfolio_session` จาก Request นำมาถอดรหัสและค้นหาข้อมูลผู้ใช้ในฐานข้อมูล MongoDB โดยต้องมีสถานะเป็น `active` เท่านั้น
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์ผู้ใช้ `SafeUser` หรือ `null` หากไม่ได้ล็อกอิน

### 1.14 `requireApiUser(roles)`
* **หน้าที่:** ป้อมยามตรวจสิทธิ์ (Middleware Guard) สำหรับเรียกใช้ใน API Routes
* **การทำงาน:** เรียก `getCurrentUser()` หากไม่พบบัญชีจะส่ง Response HTTP 401 (Unauthorized) หากพบบัญชีแต่สิทธิ์ไม่ตรงตามที่ระบุใน `roles` (เช่น นักศึกษาพยายามเข้า API ของ Admin) จะส่ง HTTP 403 (Forbidden)
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์ `{ user, response }`

## 2. ระบบเชื่อมต่อฐานข้อมูล (`lib/mongodb.ts`)

ทำหน้าที่บริหารจัดการ Connection Pool ระหว่างเว็บเซิร์ฟเวอร์กับฐานข้อมูล MongoDB Atlas

### 2.1 `getMongoClient()`
* **หน้าที่:** สร้างและส่งคืน Connection Client ของ MongoDB แบบ Singleton
* **การทำงาน:** ใช้เทคนิคแคช Client ไว้ใน `globalThis` เพื่อป้องกันการเปิด Connection ซ้ำซ้อน ซึ่งช่วยลดภาระของฐานข้อมูลและทำให้ระบบทำงานได้รวดเร็วมาก
* **ผลลัพธ์ที่คืนค่า:** Promise ของ `MongoClient`

### 2.2 `getDb()`
* **หน้าที่:** ดึงอินสแตนซ์ฐานข้อมูล (Database Instance) พร้อมใช้งาน
* **การทำงาน:** รอการเชื่อมต่อจาก `getMongoClient()` แล้วเลือกฐานข้อมูลตามชื่อที่กำหนดใน `.env.local`
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์ `Db` ของ MongoDB

### 2.3 `ensureIndexes()`
* **หน้าที่:** สร้างดัชนี (Indexes) ในฐานข้อมูลโดยอัตโนมัติ เพื่อให้ค้นหาข้อมูลได้อย่างรวดเร็วระดับมิลลิวินาที
* **การทำงาน:** สร้าง Unique Index บน `email`, `studentId`, `slug` และดัชนีบน `role`, `status` และเซสชัน
* **ผลลัพธ์ที่คืนค่า:** Promise เมื่อสร้างดัชนีเสร็จสิ้น

## 3. ระบบจัดการเรซูเม่และเทมเพลต (`lib/portfolio.ts`)

ทำหน้าที่เป็นสมองกลของ Portfolio Engine ดูแลการวาง Layout กริด เทมเพลต และการตรวจสอบข้อมูล

### 3.1 `getTemplateDefinition(id)`
* **หน้าที่:** ดึงโครงสร้างเทมเพลตสำเร็จรูปตามรหัสที่เลือก (เช่น `professional`, `modern`, `creative`, `minimal`, `academic`, `compact`)
* **การทำงาน:** ค้นหาในคลังนิยามเทมเพลต หากไม่พบจะคืนค่าเทมเพลตเริ่มต้น (Professional)
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์โครงสร้างเทมเพลต `TemplateDefinition`

### 3.2 `pickSetting(value, options, fallback)`
* **หน้าที่:** ตรวจสอบความถูกต้องของค่าคอนฟิก (Data Whitelisting)
* **การทำงาน:** เช็กว่าค่าที่ส่งเข้ามา อยู่ในรายการตัวเลือกที่อนุญาตหรือไม่ หากไม่อยู่ จะใช้ค่าเริ่มต้น (`fallback`) แทน ป้องกันค่าแปลกปลอม
* **ผลลัพธ์ที่คืนค่า:** ค่าคอนฟิกที่ถูกต้อง

### 3.3 `clampNumber(value, fallback, min, max)`
* **หน้าที่:** ควบคุมตัวเลขให้อยู่ในช่วงที่ปลอดภัย
* **การทำงาน:** แปลงข้อมูลเป็นตัวเลข หากไม่ใช่ตัวเลขจะใช้ค่า fallback และบังคับให้อยู่ระหว่างค่าต่ำสุด (`min`) และสูงสุด (`max`)
* **ผลลัพธ์ที่คืนค่า:** ตัวเลขจำนวนเต็มที่ปลอดภัย

### 3.4 `defaultSectionSettings(section)`
* **หน้าที่:** สร้างการตั้งค่าเริ่มต้นของแต่ละบล็อกเนื้อหา
* **การทำงาน:** กำหนดค่าการแสดงหัวข้อ, การจัดชิดซ้าย, ระยะขอบ (padding), ความโค้งมน (radius), เงา (shadow), และสไตล์การแสดงรายการ
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์การตั้งค่าเริ่มต้น

### 3.5 `sanitizeSectionSettings(section)`
* **หน้าที่:** ทำความสะอาดและตรวจสอบความปลอดภัยของการตั้งค่าในบล็อกเนื้อหา
* **การทำงาน:** นำการตั้งค่าเดิมมาผ่าน `pickSetting` เทียบกับค่ามาตรฐาน ป้องกันการแทรกค่าอันตราย
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์การตั้งค่าที่ปลอดภัย

### 3.6 `sanitizeGridPlacement(gp)`
* **หน้าที่:** ตรวจสอบตำแหน่งกริด (Grid Column & Row) บนผืนผ้าใบ
* **การทำงาน:** บังคับให้ Column Start อยู่ระหว่าง 1-13 และ Row ไม่เกิน 20 เพื่อให้การจัดหน้าเว็บแสดงผลอย่างสวยงาม ไม่ล้นจอ
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์ตำแหน่งกริด `{ colStart, colEnd, rowStart, rowEnd }`

### 3.7 `applyTemplate(templateId, existingSections, user)`
* **หน้าที่:** สับเปลี่ยนโครงสร้างหน้าตาของเรซูเม่ตามเทมเพลตใหม่ โดยที่**เนื้อหาเดิมของนักศึกษาไม่สูญหาย**
* **การทำงาน:** ดึงรายการบล็อกจากเทมเพลตใหม่ หากบล็อกใดนักศึกษาเคยกรอกไว้แล้ว จะดึงเนื้อหาเดิมมาใส่ในตำแหน่งใหม่ หากเป็นบล็อกใหม่ จะเติมข้อมูลตัวอย่างเริ่มต้นให้
* **ผลลัพธ์ที่คืนค่า:** อาเรย์ของบล็อกเนื้อหาชุดใหม่ที่จัดตำแหน่งตามเทมเพลตเรียบร้อยแล้ว

### 3.8 `getDefaultContent(type, user)`
* **หน้าที่:** สร้างข้อความตัวอย่างเริ่มต้นเมื่อเพิ่มบล็อกใหม่
* **การทำงาน:** นำชื่อ-สกุล อีเมล และสาขาของนักศึกษามาเติมลงใน Profile, ส่วนหมวดทักษะจะเติมตัวอย่าง "Next.js, MongoDB, TypeScript"
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์เนื้อหา `{ body, items, imageUrl }`

### 3.9 `slugify(input)`
* **หน้าที่:** แปลงข้อความเป็นชื่อ URL ที่เป็นมิตร (Web Friendly Slug)
* **การทำงาน:** ตัดอักขระพิเศษออกทั้งหมด แปลงเป็นตัวพิมพ์เล็ก และคั่นด้วยเครื่องหมายขีดกลาง เช่น `"Somchai Portfolio"` $\rightarrow$ `"somchai-portfolio"`
* **ผลลัพธ์ที่คืนค่า:** ข้อความ String slug

### 3.10 `uniqueSlug(seed, ignorePortfolioId)`
* **หน้าที่:** สร้างชื่อลิงก์ URL ที่ไม่ซ้ำกับคนอื่นในฐานข้อมูลอย่างแน่นอน
* **การทำงาน:** นำชื่อหรือรหัสนักศึกษามาทำ `slugify` แล้วตรวจเช็กในฐานข้อมูล หากซ้ำ จะเติมเลขต่อท้าย เช่น `-2`, `-3` ไปเรื่อยๆ จนกว่าจะได้ชื่อที่ไม่ซ้ำ
* **ผลลัพธ์ที่คืนค่า:** ข้อความ String slug ที่ไม่ซ้ำใคร

### 3.11 `getOrCreatePortfolio(userId)`
* **หน้าที่:** ดึงแฟ้มสะสมผลงานของนักศึกษาขึ้นมา หากยังไม่เคยมี ระบบจะสร้างแฟ้มเริ่มต้นให้อัตโนมัติทันที
* **การทำงาน:** ค้นหาในคอลเลกชัน `portfolios` หากพบจะคืนค่าทันที หากไม่พบ จะดึงข้อมูลนักศึกษามาสร้างเรซูเม่ชุดแรกในสถานะ "แบบร่าง (Draft)" พร้อมเทมเพลต Professional
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์เอกสาร Portfolio จากฐานข้อมูล

### 3.12 `serializePortfolio(portfolio)`
* **หน้าที่:** แปลงข้อมูลจาก MongoDB ให้อยู่ในรูปแบบ JSON สากลสำหรับส่งให้หน้าบ้าน
* **การทำงาน:** แปลง `ObjectId` เป็น String, แปลง `Date` เป็น ISO String และเรียงลำดับบล็อกเนื้อหาตามลำดับ `order`
* **ผลลัพธ์ที่คืนค่า:** ออบเจกต์ `SerializedPortfolio`

### 3.13 `sanitizeSections(sections)`
* **หน้าที่:** ตรวจสอบความถูกต้องและตัดทอนความยาวข้อมูลในทุกบล็อกก่อนบันทึกลงฐานข้อมูล
* **การทำงาน:** จำกัดความยาวชื่อหัวข้อไม่เกิน 80 ตัวอักษร, ข้อความบรรยายไม่เกิน 4,000 ตัวอักษร, รูปภาพไม่เกินขนาดที่กำหนด เพื่อป้องกันฐานข้อมูลล้น
* **ผลลัพธ์ที่คืนค่า:** อาเรย์ของบล็อกเนื้อหาที่ผ่านการคลีนข้อมูลแล้ว

## 4. ระบบบริการข้อมูลฝั่งเซิร์ฟเวอร์ (API Endpoints)

### 4.1 `POST /api/auth/login` (`app/api/auth/login/route.ts`)
* **หน้าที่:** ให้บริการตรวจสอบการเข้าสู่ระบบ
* **การทำงาน:** รับรหัสนักศึกษา/อีเมล และรหัสผ่าน ค้นหาในฐานข้อมูล ตรวจสอบรหัสผ่านผ่าน `verifyPassword` หากถูกต้องจะสร้างโทเคนและแนบคุกกี้ส่งกลับไป พร้อมแจ้งบทบาทผู้ใช้ (`role`)

### 4.2 `POST /api/auth/logout` (`app/api/auth/logout/route.ts`)
* **หน้าที่:** ออกจากระบบ
* **การทำงาน:** เรียก `clearSessionCookie` เพื่อล้างคุกกี้ออกจากเบราว์เซอร์

### 4.3 `POST /api/auth/change-password` (`app/api/auth/change-password/route.ts`)
* **หน้าที่:** ให้ผู้ใช้เปลี่ยนรหัสผ่านของตนเอง
* **การทำงาน:** ตรวจสอบว่าล็อกอินอยู่หรือไม่ ตรวจสอบรหัสผ่านเดิมว่าถูกต้องหรือไม่ แล้วจึงแฮชรหัสผ่านใหม่บันทึกลงฐานข้อมูล

### 4.4 `GET /api/portfolio/me` (`app/api/portfolio/me/route.ts`)
* **หน้าที่:** ดึงข้อมูล Portfolio ปัจจุบันของนักศึกษาที่กำลังล็อกอินอยู่

### 4.5 `PUT /api/portfolio/me` (`app/api/portfolio/me/route.ts`)
* **หน้าที่:** บันทึกการแก้ไขข้อมูลเรซูเม่ (ทั้งแบบร่างและการจัดหน้า)
* **การทำงาน:** ตรวจสอบสิทธิ์นักศึกษา คลีนข้อมูลบล็อกด้วย `sanitizeSections` อัปเดตสไตล์และบันทึกลงฐานข้อมูล

### 4.6 `POST /api/portfolio/me/publish` (`app/api/portfolio/me/publish/route.ts`)
* **หน้าที่:** เปิดแสดงผลงานสู่สาธารณะ
* **การทำงาน:** เปลี่ยนสถานะจาก `draft` เป็น `published` และบันทึกเวลาที่เผยแพร่ (`publishedAt`)

### 4.7 `POST /api/portfolio/me/unpublish` (`app/api/portfolio/me/unpublish/route.ts`)
* **หน้าที่:** ปิดการแสดงผลงานสาธารณะชั่วคราว
* **การทำงาน:** เปลี่ยนสถานะกลับมาเป็น `draft` ทำให้คนภายนอกเปิดดูไม่ได้

### 4.8 `GET /api/students` (`app/api/students/route.ts`)
* **หน้าที่:** ดึงรายชื่อนักศึกษาทั้งหมดในระบบสำหรับหน้าอาจารย์ (Admin Guard)

### 4.9 `POST /api/students` (`app/api/students/route.ts`)
* **หน้าที่:** อาจารย์สร้างบัญชีนักศึกษาใหม่เข้าระบบ
* **การทำงาน:** ตรวจสอบว่ารหัสนักศึกษาและอีเมลไม่ซ้ำ แฮชรหัสผ่านเริ่มต้น และบันทึกบัญชีใหม่ลงฐานข้อมูล

### 4.10 `PUT /api/students/[id]` (`app/api/students/[id]/route.ts`)
* **หน้าที่:** อาจารย์แก้ไขข้อมูลส่วนตัวของนักศึกษา (เช่น แก้ไขชื่อ หรืออีเมล)

### 4.11 `PATCH /api/students/[id]` (`app/api/students/[id]/route.ts`)
* **หน้าที่:** อาจารย์สั่งรีเซ็ตรหัสผ่านให้นักศึกษา หรือสลับสถานะบัญชี (Active/Inactive)

### 4.12 `DELETE /api/students/[id]` (`app/api/students/[id]/route.ts`)
* **หน้าที่:** อาจารย์ลบบัญชีนักศึกษาและแฟ้มผลงานที่เกี่ยวข้องออกจากระบบ

## 5. ระบบการทำงานฝั่งหน้าบ้าน (Client Frontend Components)

### 5.1 สตูดิโอออกแบบเรซูเม่ (`components/StudentEditor.tsx`)
* **`handleAddBlock(type)`:** เพิ่มการ์ดหมวดหมู่ใหม่ลงบนหน้าจอตามที่ผู้ใช้คลิกเลือก
* **`handleRemoveBlock(id)`:** ลบการ์ดที่ไม่ต้องการออกจากผืนผ้าใบ พร้อมเปิดหน้าต่างยืนยันความปลอดภัย
* **`handleMoveBlock(id, direction)`:** เลื่อนลำดับการ์ดขึ้นหรือลงบนตาราง
* **`handleToggleVisibility(id)`:** ซ่อนหรือเปิดแสดงการ์ดบนเรซูเม่จริงโดยไม่ต้องลบเนื้อหาทิ้ง
* **`updateSelectedSection(patch)`:** อัปเดตคุณสมบัติของการ์ดที่กำลังเลือกอยู่ (เช่น เปลี่ยนสี เปลี่ยนฟอนต์ พิมพ์ข้อความใหม่)
* **`handleTemplateChange(templateId)`:** สลับเทมเพลตหน้าตาเรซูเม่ 6 สไตล์ในคลิกเดียว
* **`handleSaveDraft()`:** ส่งคำขอ HTTP PUT ไปบันทึกข้อมูลแบบร่างลงเซิร์ฟเวอร์
* **`handlePublish()`:** ส่งคำขอ HTTP POST เพื่อเปิดแสดงผลงานสู่สาธารณะทันที

### 5.2 ศูนย์ควบคุมผู้ดูแลระบบ (`components/AdminPanel.tsx`)
* **`filtered` (Memoized Filter):** ค้นหารายชื่อนักศึกษาตามชื่อ รหัส หรืออีเมลแบบทันทีโดยไม่ต้องรีเฟรชหน้าเว็บ
* **`handleCreateStudent(e)`:** ส่งข้อมูลฟอร์มเพิ่มนักศึกษาไปยัง API
* **`handleResetPassword(student)`:** ส่งคำสั่งรีเซ็ตรหัสผ่านให้นักศึกษาที่ลืมรหัส
* **`handleToggleStatus(student)`:** สลับการเปิด/ปิดการใช้งานบัญชีนักศึกษา

### 5.3 จัดการโปรไฟล์นักศึกษา (`components/StudentAccountManager.tsx`)
* **`handleSaveProfile(e)`:** ฟังก์ชันบันทึกชื่อ-สกุล และชั้นปีของนักศึกษา
* **`handleChangePassword(e)`:** ฟังก์ชันตรวจสอบและอัปเดตรหัสผ่านใหม่

### 5.4 การแสดงผลเรซูเม่ (`components/ResumeRenderer.tsx`)
* **หน้าที่:** แปลงข้อมูลจากโครงสร้าง JSON ออกมาเป็นหน้าเว็บจริงและจัดหน้าตาสำหรับสั่งพิมพ์เป็น PDF ตามมาตรฐานกระดาษ A4 สากล
